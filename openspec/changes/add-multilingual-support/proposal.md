## Why

RefleK's 当前将用户可见文案以及日期、数字格式直接写死为英文和 `en-US`，非英语用户无法获得一致、完整的本地化体验。需要建立统一的多语言能力，首期交付英文和简体中文，并允许后续在不修改业务组件的前提下增加其他语言。

## What Changes

- 为桌面应用增加 `en`、`zh-CN` 两种语言设置；首次没有已保存语言时检测一次操作系统当前语言，选择并持久化 `en` 或 `zh-CN`，以后不再自动跟随系统变化。
- 使用按业务域拆分的本地语言资源管理所有固定用户界面文案，英文作为基准和最终回退语言。
- 对翻译 key 提供 TypeScript 静态检查，并在构建期同时校验语言包结构、插值变量和代码引用。
- 语言切换即时生效，并同步更新日期、时间、数字、时长、星期和月份等区域格式。
- 将需要展示给用户的后端失败结果暴露为稳定错误码和结构化参数，由前端完成翻译；后端日志保持英文。
- 固定简体中文核心术语、中文字体回退和富文本翻译规则，避免同义词漂移和不安全 HTML 注入。
- 增加隔离测试资料、语言资源完整性校验以及英文、简体中文界面的确定性构建和关键页面验证。
- 保留场景名、Benchmark 官方名称和等级、玩家昵称、文件路径、版本号、技术日志及其他外部业务数据的原始内容。

## Capabilities

### New Capabilities

- `multilingual-user-interface`: 定义语言选择、资源加载、即时切换、区域格式、错误本地化、英文回退和非翻译数据边界。

### Modified Capabilities

无。

## Impact

- 前端新增 `i18next`、`react-i18next` 依赖和集中式 i18n 初始化、资源及格式化模块。
- 前端各业务模块需要把固定用户可见英文迁移为稳定语义键。
- Go Settings 模型及其默认值、校验和持久化逻辑增加语言字段。
- Settings 保存队列和重置流程需要保证语言切换不会被陈旧完整快照覆盖。
- Replay 和 Screen Capture 等跨 Wails 边界的用户可见状态需要从自由文本改为统一错误码和结构化参数。
- Wails 生成的 TypeScript 绑定会随 Settings 和错误结构变化而重新生成。
- 测试增加隔离用户目录和脱敏训练资料，不读取或修改开发机真实 RefleK's 配置与训练数据。
- 不改变训练记录、Benchmark、场景、回放和同步数据的存储格式或业务语义。
